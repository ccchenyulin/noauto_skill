## 核心行为准则

### 🔴 原则一：禁止臆测现有代码

在任何涉及修改、修复、添加功能到已有代码的场景下，你必须：

1. 明确告知用户："请将需要修改的文件完整代码粘贴到对话框中"
2. 等待用户粘贴代码后，才能开始分析和修改
3. **严禁根据印象、上下文猜测、或自行假设现有代码的内容**
4. 如果用户粘贴的代码不完整（如只粘贴了一部分），必须再次要求补全

### 🔴 原则二：信息补全引导

当发现实现功能所需的关键信息缺失时，你必须：

1. 明确指出当前缺失的具体信息项
2. 提供清晰的获取路径指引
3. 暂停代码生成，等待用户补充信息

### 🔴 原则三：最小改动原则

每次修改必须：

1. **只改动本次任务涉及的代码**，不得顺手修改其他地方
2. 修改前输出原始代码片段，修改后输出新代码片段，方便对比和回滚
3. 在变更记录中清楚说明改了什么、为什么改
4. 修改前必须显式列出本次改动涉及的所有位置（文件名 + 大致行号），作为追溯依据

**默认允许联网查询技术资料**。联网只发生在**分析需求之后、写代码之前**，一次性查完再写，不在写代码过程中中途联网。

| 场景 | 是否联网 | 查什么 |

| 需要调用 `comfy.utils` 等内部工具函数，但不在已知公开列表中 | ✅ 联网 | 确认函数签名在 0.20.1 中是否存在且稳定 |
| 用户明确要求使用 V3 新特性 | ✅ 联网 | 查 V3 schema 当前文档 |
| 节点在某次 ComfyUI 更新后突然失效 | ✅ 联网 | 查该版本 changelog |
| 需要调用外部 HTTP API 或第三方库 | ✅ 联网 | 搜索该工具的官方文档或 GitHub 示例 |
| 同一问题经过一轮修复后仍未解决 | ✅ 联网 | 搜索相关 issue，不得凭猜测继续修改 |

### A-2. 开发流程（新节点必须按此顺序执行）

1. **需求确认**：用自己的理解复述用户需求，明确节点的输入、输出、核心功能，等待用户确认后才继续

8. 输出进度快照（**仅首次创建或有实质变更时**输出，无变更则写"本轮无变更，快照继承上轮"）

### B-0. 诊断阶段（所有修复的强制起点）

**触发条件**：用户描述节点报错、行为异常、运行结果不对。

**无论用户有没有提供代码和日志，必须先执行此阶段。**

执行步骤：

1. 要求用户描述（或补充）以下信息：
   - 错误的表现形式（报错信息 / 结果不对 / 没有反应）
   - 错误发生在哪个阶段（ComfyUI 启动时 / 节点加载时 / 节点执行时 / 前端交互时）

2. 根据错误类型，判断问题落在哪一层，并列出需要收集的信息：

| 错误类型 | 问题所在层 | 必须收集的信息 |
|---|---|---|
| 节点不出现在 UI | 注册层 | `__init__.py` 导入段 + ComfyUI 启动日志首屏 |
| 节点执行时 Python 报错 | 逻辑层 | 完整节点代码 + 完整启动及运行日志 |
| HTTP 请求返回 4xx/5xx | 接口契约层 | 浏览器 F12 → Network 完整请求记录（URL + 状态码 + 响应体）+ 后端注册代码 |
| 前端 JS 行为异常（按钮无反应、报错等） | 前端层 | 浏览器 F12 → Console 完整错误信息 + JS 代码 |
| JS 修改后前端无变化 | 前端层 | 先确认是否执行了**强制刷新**（Ctrl+Shift+R，普通刷新无效）；若强制刷新后仍无效：查 F12 → Console 是否有 import 错误，确认 `js/` 目录是否已被 ComfyUI 注册（首次创建目录需重启） |
| 文件读写失败 | 环境层 | 实际文件路径 + 是否存在 + 权限 |
| 模型加载失败 | 环境层 | `pip list` 输出 + `folder_paths` 返回值 |

3. 收集到对应信息后，用中文列出**当前对这个系统的所有假设**，并逐条说明如何验证：

```
当前假设列表：
- 假设①：路由注册代码已正确执行 → 验证方式：查启动日志中是否出现注册成功的打印
- 假设②：前端请求的 URL 与后端注册路径完全一致 → 验证方式：F12 Network 对比
- 假设③：...
```

4. 根据假设验证结果，确定根本原因后，再进入 B-1 或 B-2。

**在假设列表未验证完毕之前，禁止进行任何代码修改。**

### B-0 分流规则

- **逻辑层问题，且用户已提供日志** → 直接进入 B-2（修复）

### B-3. 停损机制（强制触发）

**触发条件**：同一个修复思路（不是同一段代码，而是同一种假设和方向）失败超过 **2 次**。

执行步骤：
1. **立即停止当前修复方向**
2. 显式声明：当前思路已失败 N 次，停止继续在此方向尝试
3. **强制回到 B-0 诊断阶段**，重新列出假设列表，标记哪些假设已被证伪
4. 根据新的假设列表，选择新方向后才能继续

**禁止以"换一种实现方式"为理由绕过停损。换实现方式但假设不变，仍然计入失败次数。**

1. 立即联网搜索该服务的 API 文档或源码
2. 同时要求用户从浏览器 F12 → Network 复制成功请求的 cURL 命令

### 2. 图像张量规范

ComfyUI 图像 Tensor 格式：

- 图像：`[B, H, W, C]`（批次、高度、宽度、通道），值域 `0.0~1.0`（float32）
- Mask：`[B, H, W]`，值域 `0.0~1.0`（float32），**注意：不是 bool，不是 0/255 的 uint8**

要求：
- 保持 batch 维度
- 不破坏 tensor dtype
- 不丢失 device（CPU/GPU 位置）
- **修改张量前必须先 `.clone()`**，严禁直接修改传入的原始张量（否则会污染上游节点的数据）

#### 常用图像操作

- **维度转换**：很多 PyTorch 操作（如 interpolate）要求通道在前 `[B, C, H, W]`。用 `.movedim(-1, 1)` 把通道从最后移到第二维，用 `.movedim(1, -1)` 移回来。
- **调整尺寸**：`comfy.utils.common_upscale(tensor, width, height, method, crop)` 输入必须是 `[B, C, H, W]` 格式。
- **批量对齐**：如果两个图像张量的 B 不同，用 `comfy.utils.repeat_to_batch_size(tensor, target_batch)` 统一。
- **通道对齐**：合成前用 `node_helpers.image_alpha_fix(image1, image2)` 对齐通道数。

#### 设备管理

- **计算设备**：耗时操作前把张量移到 `comfy.model_management.get_torch_device()`（通常是 GPU）。
- **输出设备**：最终返回前用 `.to(comfy.model_management.intermediate_device())` 移回中间设备。
- 日志中应打印 `tensor.device`，方便排查设备位置错误。

#### 长循环中断检查

长循环（如逐帧处理）中必须插入中断检查，让用户点"取消"时能及时响应：

```python
import comfy.model_management
comfy.model_management.throw_exception_if_processing_interrupted()
```

### 3. 节点 API 规范（V1）

所有节点必须包含：`INPUT_TYPES`、`RETURN_TYPES`、`RETURN_NAMES`、`FUNCTION`、`CATEGORY`

根据节点功能，按需添加以下可选属性：

| 属性 | 类型 | 说明 |
|------|------|------|
| `OUTPUT_NODE` | `bool` | 设为 `True` 表示该节点是终端输出节点（如保存图片），ComfyUI 会强制执行它。默认不设置（等同于 False）。 |
| `IS_CHANGED` | classmethod | 控制节点缓存行为。ComfyUI 比较本次返回值和上次返回值，**两次返回值不同时**才重新执行节点。**不要返回 `True`**（`True == True` 会导致节点反而不重新执行）。要让节点每次都强制重新执行，返回 `float("NaN")`。 |
| `VALIDATE_INPUTS` | classmethod | 在节点执行前校验输入合法性。返回 `True` 表示校验通过；返回字符串表示校验失败并显示给用户。**强烈推荐**在参数有约束条件时使用。 |

标准模板：

```python
class NodeName:
    @classmethod
    def INPUT_TYPES(cls):
        return {
            "required": {},
            "optional": {},
            # 如需访问完整 prompt 或工作流元数据，添加 hidden（不在 UI 显示）：
            # "hidden": {
            #     "unique_id": "UNIQUE_ID",
            #     "prompt": "PROMPT",
            #     "extra_pnginfo": "EXTRA_PNGINFO"
            # }
        }

    RETURN_TYPES = ()
    RETURN_NAMES = ()
    FUNCTION = "run"
    CATEGORY = ""
    # OUTPUT_NODE = True  # 如果是终端输出节点，取消此行注释

    def run(self):
        pass
```

#### Optional 输入的 None 处理（必须遵守）

**凡是 `optional` 中声明的输入，用户可以不连接，此时传入值为 `None`。**
在使用 optional 输入之前，必须先判断是否为 None：

```python
def run(self, image, mask=None):
    # ✅ 正确：先检查 None
    if mask is not None:
        logger.debug(f"[MyNode][DEBUG] mask.shape={mask.shape}")
        # 才能对 mask 做张量操作
    else:
        logger.info(f"[MyNode][INFO] mask 未连接，跳过遮罩处理")

    # ❌ 错误：直接操作，mask 为 None 时立即崩溃
    # result = image * mask
```

#### 推理代码必须包裹 `torch.no_grad()`

凡是不需要训练梯度的推理操作（节点执行几乎全部属于此类），必须包裹在 `torch.no_grad()` 中，否则 PyTorch 会保留所有中间计算结果用于反向传播，白白浪费大量 VRAM：

```python
import torch

def run(self, image):
    with torch.no_grad():
        # 所有推理计算放在这里
        result = some_model(image)
    return (result,)
```

#### 模型加载不得放在 execute 函数里

每次节点运行都重新加载模型会导致每次执行耗时数十秒。模型应该在类级别缓存，只在首次运行或参数变化时才重新加载：

```python
class MyModelNode:
    # 类级别缓存，所有实例共享
    _model_cache = None
    _model_path_cache = None

    def run(self, model_path, image):
        # 只在模型路径变化时才重新加载
        if MyModelNode._model_cache is None or MyModelNode._model_path_cache != model_path:
            logger.info(f"[MyModelNode][INFO] 加载模型：{model_path}")
            MyModelNode._model_cache = load_model(model_path)
            MyModelNode._model_path_cache = model_path
        else:
            logger.info(f"[MyModelNode][INFO] 使用缓存模型，跳过加载")

        with torch.no_grad():
            result = MyModelNode._model_cache(image)
        return (result,)
```

#### IS_CHANGED 正确用法

```python
@classmethod
def IS_CHANGED(cls, image, threshold, **kwargs):
    return float("NaN")

@classmethod
def IS_CHANGED(cls, file_path, **kwargs):
    import hashlib
    with open(file_path, "rb") as f:
        return hashlib.sha256(f.read()).hexdigest()
```

#### VALIDATE_INPUTS 用法示例

```python
@classmethod
def VALIDATE_INPUTS(cls, threshold, mode, **kwargs):
    if threshold < 0.0 or threshold > 1.0:
        return f"阈值必须在 0.0 到 1.0 之间，当前值为 {threshold}"
    if mode not in ["fast", "precise"]:
        return f"模式只能是 'fast' 或 'precise'，当前值为 '{mode}'"
    return True
```

### 7. 日志规范（极尽详细）

**核心要求：日志是用户唯一的调试手段，必须极尽详细。宁可日志过多，不可有任何遗漏。**

#### 日志工具

```python
from .core.logger import logger
# 不支持时退回：
print(f"[节点类名][级别] 描述信息")
```

#### 日志分级规范

| 级别 | 使用场景 |
|------|----------|
| `DEBUG` | 变量值、张量形状、中间计算结果、循环进度 |
| `INFO` | 流程节点、分支选择、阶段开始/结束 |
| `WARNING` | 非致命异常、降级处理、参数超出推荐范围 |
| `ERROR` | 捕获到异常、执行失败（含完整堆栈） |

#### 必须打日志的位置（全部必填，不得遗漏）

1. **方法入口**：打印所有输入参数的值和张量 shape/dtype/device
2. **每个条件分支入口**：说明进入了哪个分支，以及触发条件的值
3. **每次张量操作前后**：打印操作名称 + 操作前后的 shape、dtype、device
4. **每次循环的关键步骤**：打印当前迭代索引和关键中间值
5. **调用外部函数/库前后**：打印传入参数和返回结果的关键信息
6. **每个 try 块入口**：说明即将尝试什么操作
7. **每个 except 块**：打印异常类型、异常信息、完整堆栈（`exc_info=True`）
8. **方法出口**：打印所有输出的关键信息（shape、值范围等）
9. **optional 输入的 None 判断处**：无论是否为 None 都要打日志说明

缺失任意位置的日志视为代码不合格，必须补全后才能提交。

#### 日志示例（标准）

```python
def run(self, image, threshold, mode, mask=None):
    logger.info(f"[MyNode][INFO] ══ 节点开始执行 ══")
    logger.debug(f"[MyNode][DEBUG]   image.shape  = {image.shape}")
    logger.debug(f"[MyNode][DEBUG]   image.dtype  = {image.dtype}")
    logger.debug(f"[MyNode][DEBUG]   image.device = {image.device}")
    logger.debug(f"[MyNode][DEBUG]   threshold    = {threshold}")
    logger.debug(f"[MyNode][DEBUG]   mode         = {mode}")
    logger.debug(f"[MyNode][DEBUG]   mask         = {'已连接，shape=' + str(mask.shape) if mask is not None else '未连接(None)'}")

    if image.ndim != 4:
        logger.error(f"[MyNode][ERROR] 输入图像维度错误，期望 4 维，实际 {image.ndim} 维")
        raise ValueError(f"[MyNode] 输入图像必须是 4 维张量 [B,H,W,C]，当前维度为 {image.ndim}")

    # 克隆张量，避免污染上游数据
    logger.debug(f"[MyNode][DEBUG] 克隆输入张量，避免修改原始数据")
    image = image.clone()

    try:
        with torch.no_grad():
            logger.info(f"[MyNode][INFO] 判断执行模式，当前 mode={mode}")
            if mode == "fast":
                logger.info(f"[MyNode][INFO] 进入快速模式分支")
            else:
                logger.info(f"[MyNode][INFO] 进入精细模式分支")

            logger.debug(f"[MyNode][DEBUG] 即将执行阈值过滤，threshold={threshold}")
            result = image * threshold
            logger.debug(f"[MyNode][DEBUG] 阈值过滤完成，result.shape={result.shape}，值范围=[{result.min():.4f}, {result.max():.4f}]")

        logger.info(f"[MyNode][INFO] ══ 节点执行完成 ══")
        return (result,)

    except ValueError as e:
        logger.error(f"[MyNode][ERROR] 数值错误：{e}", exc_info=True)
        raise
    except Exception as e:
        logger.error(f"[MyNode][ERROR] 未知错误：{e}", exc_info=True)
        raise
```

### 8. 错误处理规范

1. **捕获具体异常优先**：能预判的错误先单独捕获并给出中文友好提示
2. **兜底捕获 Exception**：在最外层 `except Exception as e` 兜底，记录日志后 `raise`
3. **禁止返回 None 作为图像**：出错时直接 `raise`
4. **入口合法性检查**：对关键输入做基本校验，不合法时抛出带中文说明的 `ValueError`

### 11. 前后端交互规范

本节覆盖所有涉及前端 JS 与后端 Python 通信的场景。

#### 11-1. HTTP 路由路径前缀约定

前端 `api.fetchApi("/some/path")` 实际发出的请求是 `/api/some/path`（`api.js` 会自动加 `/api` 前缀）。后端注册路由时路径**必须带 `/api` 前缀**，否则前后端路径不匹配，返回 405 但后端日志显示注册成功，极难排查：

```python
# ✅ 正确
srv.app.router.add_post("/api/customnode/mwh/xxx", handler)

# ❌ 错误：前端请求 /api/customnode/...，后端注册 /customnode/... → 405
srv.app.router.add_post("/customnode/mwh/xxx", handler)
```

**路由注册规范**：所有自定义 HTTP 路由必须集中写在 `api.py` 中，不得分散到各节点文件。`api.py` 的标准结构如下：

```python
# user_mwh/api.py
# 所有自定义后端路由集中在此文件注册

from aiohttp import web
import server


def init():
    """
    ComfyUI 启动完成后由 __init__.py 调用。
    此时 PromptServer.instance 已就绪，可以安全注册路由。
    """
    srv = server.PromptServer.instance

    # ── 在此添加路由处理函数和注册 ──

    async def example_endpoint(request):
        body = await request.json()
        return web.json_response({"result": "ok"})

    # 注意：路径必须带 /api 前缀（见上方前缀约定）
    srv.app.router.add_post("/api/customnode/mwh/example", example_endpoint)
    print("[mwh/api] ✅ 路由已注册: POST /api/customnode/mwh/example")
```

`api.py` 的 `init()` 在 `__init__.py` 中统一调用（见下方"文件更新步骤"中的补丁格式）。每次向 `api.py` 新增路由后，必须**完整重启 ComfyUI**。

#### 11-2. 前端扩展 API 标准钩子

通过 `app.registerExtension` 注册扩展，主要钩子如下：

| 钩子 | 触发时机 | 常见用途 |
|---|---|---|
| `setup()` | 扩展加载完成，仅触发一次 | 初始化全局状态、注册 api 事件监听 |
| `beforeRegisterNodeDef(nodeType, nodeData, app)` | 每个节点类型注册到 UI 之前 | 注入右键菜单、修改 widget 行为 |
| `nodeCreated(node)` | 用户在画布上创建节点实例时 | 修改特定节点实例的初始状态 |

标准扩展模板：

```javascript
import { app } from "../../scripts/app.js";
import { api } from "../../scripts/api.js";

app.registerExtension({
    name: "mwh.扩展唯一名称",  // 必须全局唯一，推荐格式：mwh.功能描述

    async setup() {
        // 不需要全局初始化时删除此钩子
    },

    async beforeRegisterNodeDef(nodeType, nodeData, app) {
        // 必须过滤节点名，否则对所有节点生效
        if (nodeData.name !== "你的节点注册名") return;

        // 注入右键菜单示例
        const getExtraMenuOptions = nodeType.prototype.getExtraMenuOptions;
        nodeType.prototype.getExtraMenuOptions = function(_, options) {
            if (getExtraMenuOptions) getExtraMenuOptions.apply(this, arguments);
            options.unshift({
                content: "菜单项名称",
                callback: async () => {
                    // 调用后端接口示例
                    const resp = await api.fetchApi("/api/customnode/mwh/xxx", {
                        method: "POST",
                        headers: { "Content-Type": "application/json" },
                        body: JSON.stringify({ key: "value" })
                    });
                    const data = await resp.json();
                }
            });
        };
    }
});
```
